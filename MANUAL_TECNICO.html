1) Pre-requisitos e setup

1.1 Build local

cargo check
cargo test --locked --workspace

1.2 Rodar GUI em simulacao segura

cargo run -- --hw-mode=sim

1.3 Rodar em live (somente com governanca)

cargo run --release --features "vendor-windows" -- \
  --hw-mode=live \
  --vendor-name=cat_comm \
  --enable-write \
  --allowlist=allowlist.example.json \
  --noninteractive-approved \
  --dry-run=false

Safe default Live exige gates Sem gate = sem escrita fisica

2) Roteiro rapido (15 min)

  1. Inicie em --hw-mode=sim.
  2. Aba Cluster: aplique throttle/brake e valide dinamica basica.
  3. Aba CAN Bus: verifique sinais, trace e saude de rede.
  4. Aba Faults: injete falha e veja impacto em Events + ECU Net.
  5. Aba UDS: teste 10 02, 22 DD 01, 14 FF FF FF.
  6. Aba Leak Lab: rode prediction, Monte Carlo e CAD ASCII do O-ring.
  7. Aba ECM Live: conecte feed e exporte CSV historico.

3) Passo a passo por aba

As 16 abas cobrem operacao completa da bancada. Use a ordem abaixo para exploracao progressiva.

3.1 Cluster

  1. Use key/ignition para simular estados Off/Acc/Crank/Run.
  2. Aplique throttle e brake gradualmente.
  3. Observe RPM, velocidade, marcha, lamps e warnings.
  4. Valide consistencia com Engine + CAN Bus.

Objetivo: baseline operacional do powertrain.

3.2 CAN Bus

  1. Modo Signals: inspecione PGNs decodificados e periodicidade.
  2. Modo Trace: veja frames crus para troubleshooting.
  3. Modo Network: confira load, erros, estado de cada bus.
  4. Use filtros por PGN/SA para deep debug.
  5. Teste injecoes (Bit/Ack/BusOff/Babbling) e exporte snapshot.

Objetivo: diagnostico de rede e robustez de comunicacao.

3.3 Events

  1. Selecione nivel minimo (Info/Warning/Critical).
  2. Filtre por subsistema (engine, can, uds, leak, ad).
  3. Correlacione timestamps com Faults e UDS log.

Objetivo: trilha causal e auditoria de comportamento.

3.4 ECU Net

  1. Verifique ECUs online/offline e estagio de boot.
  2. Confirme sincronismo entre gateway, net_mgmt e can_net.
  3. Identifique ECUs degradadas apos faults.

Objetivo: visibilidade topologica da arquitetura eletronica.

3.5 Engine

  1. Monitore temperatura, pressao de oleo, boost, torque.
  2. Acompanhe aftertreatment e estados de protecao.
  3. Valide limites contra parametros calibrados.

Objetivo: validacao funcional de ECM e saude termica/mecanica.

3.6 Faults

  1. Selecione fault no catalogo.
  2. Acione Inject e observe reacao em Engine/CAN/Events.
  3. Use Clear Faults para retorno controlado.
  4. Registre sinais antes e depois (Plots + export).

Objetivo: reproduzir cenarios de falha para RCA/PCA.

3.7 Boot

  1. Inspecione sequencia de boot por ECU.
  2. Valide tempos e address-claim.
  3. Cheque transicoes de ignition e readiness geral.

Objetivo: teste de startup e disponibilidade da rede.

3.8 Implements

  1. Controle PTO, hitch e valvulas auxiliares.
  2. Observe resposta hidraulica e limites de pressao.
  3. Correlacione com Leak Lab para impacto de vedacao.

Objetivo: validacao de implementos e carga hidraulica realista.

3.9 Params

  1. Edite parametros de simulacao de forma controlada.
  2. Aplique e acompanhe efeito imediato nos modulos.
  3. Use extremos para teste de robustez e alarms.

Objetivo: ensaio dirigido e validacao de fronteiras operacionais.

3.10 Sensors

  1. Valide GPS/IMU/Radar/Lidar/Camera individualmente.
  2. Cruze com AD para confirmar impacto de percepcao.
  3. Use este painel como base de tuning de fusion.

Objetivo: assegurar qualidade de entrada do stack autonomo.

3.11 AD

  1. Engage AD e ajuste setpoint ACC.
  2. Monitore throttle/brake/steer gerados pelo controlador.
  3. Use path planning para waypoints e observe resposta.
  4. Analise TTC/THW, lane confidence, safety status.

Objetivo: validacao de controle autonomo e seguranca operacional.

3.12 V2X

  1. Monitore DSRC/C-V2X, range, latencia e perda.
  2. Avalie alertas cooperativos e telemetria remota.
  3. Cruze eventos com AD para risco de colisao.

Objetivo: testar cooperacao veiculo-rede.

3.13 UDS

  1. Defina SA alvo (ex: 0x00 ECM, 0x03 TCM).
  2. Use presets para sessao e leitura de DIDs.
  3. Para limpeza: use workflow Clean (ClrDTC + ResetAdap).
  4. Para flash: selecione firmware .bin e execute Flash Upload.
  5. Em live real, a escrita depende de gate completo:
--enable-write + --allowlist + --noninteractive-approved + --dry-run=false

Objetivo: diagnostico e manutencao controlada por protocolo UDS.

3.14 ECM Live

  1. Detect ECMs na rede.
  2. Connect ao SA alvo.
  3. Start Retrieve Data e monitore snapshot.
  4. Stop e exporte historico CSV para analise.

Objetivo: coleta operacional para tendencia, tuning e auditoria.

3.15 Leak Lab

  1. Escolha circuito (HYD_MAIN, ENG_OIL, AC_HIGH ou custom).
  2. Aplique parametros manuais de engenharia.
  3. Rode Scenario Prediction e Monte Carlo.
  4. Use CAD ASCII para visualizar pressure point, tear-up e fragilidade.
  5. Use timeline ASCII para evolucao temporal de pressao/risco/flow.
  6. Calibracao: Select CSV -> Run Auto Calibration -> exporte report.

Objetivo: plataforma de engenharia de vedacao e risco de ruptura.

3.16 Plots

  1. Acompanhe RPM, torque, velocidade, fuel, coolant, boost, dpf.
  2. Use como suporte a investigacao de root cause.
  3. Capture comportamento antes/depois de faults e calibracoes.

Objetivo: analise temporal de sinais criticos.

5) Workflows de engenharia recomendados

Workflow A - Validacao funcional end-to-end

  1. Cluster baseline.
  2. Engine estabilidade termica.
  3. CAN Bus sem erros.
  4. Fault inject controlado.
  5. Events/Plots para evidencia.

Workflow B - Diagnostico UDS + manutencao

  1. Entrar em sessao correta.
  2. Ler DIDs criticos.
  3. Executar clean quando necessario.
  4. Flash upload somente com gate completo e janela segura.

Workflow C - Leak Engineering completo

  1. Ajuste manual inicial.
  2. Prediction + Monte Carlo.
  3. CAD ASCII + timeline ASCII.
  4. Calibracao por CSV real de bancada.
  5. Export de report por circuito/material/oleo.

6) Modo production-ready

6.1 Politica de seguranca

  • Operacao live sempre com allowlist e aprovacao explicita.
  • Dry-run ativo por default fora de janela de manutencao.
  • Logs de startup policy e trilha UDS obrigatorios.

6.2 Comandos de validacao antes de release

cargo fmt
cargo clippy --workspace --all-targets
cargo test --locked --workspace
cargo test --test io_mock

6.3 Evidencias minimas por entrega

  • snapshot de rede CAN
  • CSV de ECM live
  • report Leak Lab runtime + prediction + calibration
  • log UDS de manutencao/flash
